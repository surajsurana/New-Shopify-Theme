1 — The add-to-wishlist affordance, shown in context on a Collection card

One card component, everywhere: the heart button is added directly to the existing .ka-p-card used sitewide — Collection grid, search results, this page's own grid. No second card style. The three cards below are styled and behave exactly as they would on the real Collection page (same quick-add hover veil, same zoom-on-hover image) — only the heart is new.

Placement + behavior: top-right corner, mirroring the existing "Made to Order" badge's top-left position. Persistent, not hover-only (a save action must work on tap, where hover doesn't exist). Outline heart at rest; a click/tap fills it rosegold with a soft, quiet scale-in (the same easing as every other micro-interaction on the site) — no toast, no popup. The fill itself is the confirmation; a separate notification would be one interruption too many for what should feel like a small, private gesture. Click any heart below to try it.

2 — The Wishlist page itself, populated

Same page header register as the Collection page and Journal index — eyebrow, italic serif title, one quiet meta line (piece count) — not a hero, since this is a utility page the visitor arrives at with intent, not a page that needs to sell the brand's world to them again. The grid below is the identical .ka-p-card grid, hearts pre-filled (everything here is already saved). Click a heart to remove a piece — it fades out with a soft transition rather than snapping away instantly, and the header count updates live. Remove all three to see the empty state below take over automatically.

3 — Empty state

Same restrained voice family as the Client Diaries "Coming Soon" page and the Collection page's own empty state — quiet mark, italic serif headline, one line of muted body copy, one primary CTA. Not "coming soon" wording (the feature is live, the visitor's own list is simply empty) but the identical register: warm, unhurried, never apologetic about having nothing to show yet. A single small line under the CTA states plainly that the wishlist lives on this device — honest about what a no-login, localStorage-based wishlist actually does, without over-promising cross-device sync that isn't being built.
